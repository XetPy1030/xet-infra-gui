# ADR-0003: Секреты в Keychain (safeStorage), собственный TOTP-девайс

**Статус**: принят (2026-07-29)

## Контекст

Для «нулевого ввода» нужны пароль Teleport и источник OTP. Пользовательский 2FA-аппликейшн —
G2FA (Mac App Store): sandbox, без сетевых entitlements, **без API/URL-scheme/CLI** —
программная интеграция невозможна. Кластер разрешает TOTP (`second_factor: on`), у
пользователя уже есть два TOTP-девайса (прецедент `macbook auth` — добавлять девайсы можно).
Позже источником кредов станет собственный бэкенд-API.

## Решение

1. Хранение секретов — **Electron `safeStorage`** (ключ шифрования в macOS Keychain),
   зашифрованные blob'ы в `userData`. Не keytar (заброшен), не свой крипто-велосипед.
2. OTP — **собственный TOTP-девайс приложения**: мастер проводит через
   `tsh mfa add --type TOTP --name xet-infra-gui` (одноразовое подтверждение кодом из G2FA),
   секрет из вывода tsh сохраняется в Keychain; коды генерирует `otplib` в main-процессе.
3. Все автоматизируемые команды tsh — с `--mfa-mode=otp` (кластер предпочитает webauthn,
   который в PTY не автоматизируется и не нужен здесь).
4. Доступ к кредам — только через порт `CredentialStore`; удалённый API в будущем — второй
   адаптер того же порта. Секреты не попадают в renderer, IPC-события, логи, ring buffer.
5. Ручной ввод остаётся полноценным фолбэком на каждом шаге (PromptPipeline → AskUserHandler).

## Последствия

- (+) Полный «одно-кликовый» перелогин и старт прокси; G2FA остаётся личным девайсом пользователя.
- (−) TOTP-секрет лежит на машине (зашифрован Keychain-ключом) — сознательный компромисс
  для персонального инструмента; смягчение: девайс отзываем в один клик (`tsh mfa rm`).
- (−) Одноразовая ручная церемония регистрации девайса в wizard'е.

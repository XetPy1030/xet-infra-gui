# ADR-0002: node-pty (N-API) + @xterm/xterm 6, батчинг и ring buffer

**Статус**: принят (2026-07-29)

## Контекст

Интерактивные сессии (`tsh login`, `proxy db` с OTP, `kubectl exec -it`, psql) требуют
настоящий PTY; вывод надо рендерить в GUI и переживать закрытие окна. Поток логов
`--follow` может давать тысячи чанков в секунду.

## Решение

1. **node-pty 1.1** в main-процессе. Версия 1.1 собрана на N-API (`node-addon-api`) и ставит
   prebuild-бинарники с фолбэком на `node-gyp rebuild` — жёсткой привязки к ABI конкретной
   версии Electron и обязательного `@electron/rebuild` больше нет (в отличие от эпохи ≤1.0).
   Проверять работоспособность prebuild'а в подписанной сборке (M5).
2. **@xterm/xterm 6** + `@xterm/addon-webgl` (авто-фолбэк на DOM при потере контекста),
   `addon-fit`, `addon-search`, `addon-web-links`. Canvas-рендерер устарел — не используем.
3. **Батчинг**: PTY-чанки копятся в main и сбрасываются раз в 8–16 мс одним IPC-событием
   `session/data {chunks[]}` (подход VS Code). **Backpressure**: колбэк `xterm.write`
   подтверждает переваренные байты; при отставании — `pty.pause()/resume()`.
4. **Ring buffer** сырых байтов (256 КБ/сессия) в main — replay в свежий xterm при
   переоткрытии окна. `@xterm/headless` + serialize отклонён на текущем этапе: точнее,
   но дороже по памяти и сложности; ring buffer покрывает потребность десятка сессий.
5. Не-интерактивные потоки (logs --follow, one-shot exec) идут без PTY — обычный spawn
   с теми же батчингом/backpressure.

## Последствия

- (+) Сессии переживают окно; UI не подвисает на шумных логах.
- (−) Двойная механика PTY/exec — цена за простоту 90% структурированных запросов.
- (−) При отсутствии prebuild под свежий Electron потребуется локальная сборка node-gyp
  (Xcode CLT) — фиксируем версию Electron осознанно.

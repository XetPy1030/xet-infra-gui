# 06 — Финальная проверка этапа (чек-лист для ИИ-агента)

Применять, когда работа кажется законченной: код написан, тесты зелёные, хочется сказать
«этап готов». Цель — поймать то, что систематически ускользает именно в этом проекте
(Electron + внешний CLI + живой кластер), и записать честный результат.

Чек-лист не про «поставить галочки»: каждый пункт — это либо команда, либо конкретный вопрос,
на который надо ответить фактом. Если пункт неприменим — так и сказать, а не молча пропустить.

## 0. Правило номер один: зелёные тесты ничего не доказывают

Всё, что реально ломалось в M0–M2, ломалось **вне** зоны юнит-тестов:

| Что поймали тесты                                             | Что поймал только живой прогон                                                           |
|---------------------------------------------------------------|------------------------------------------------------------------------------------------|
| разбор JSON, маски подов, FSM-переходы, backoff, дедуп потока | пароль, испорченный авто-ответом xterm (M0)                                              |
| формат аргументов команд                                      | `ERROR:` с ANSI-раскраской в UI и нераспознанный «нужен перелогин» (M2)                  |
| выбор свежайшего пода на фикстуре                             | kube-табы, вечно висящие в «запускается» (M2)                                            |
| дословные аргументы `kubectl logs`                            | **логи не шли вообще**: tsh под PTY ждал ответа терминала, который резал наш фильтр (M2) |
| кэш и инвалидация                                             | `get pods` — это мегабайты и секунды, а UI дёргал его на каждый чих (M2)                 |

Вывод: **живой прогон обязателен**, а фейковый `tsh` годится только для того, чего вживую не
воспроизвести (протухший серт, недоступное окружение, редкий сбой).

## 1. Статика (быстро, но это только вход)

```bash
npm test && npm run typecheck && npm run lint && npm run build
```

- Пройтись по `git diff --stat`: у каждого нового модуля есть тест? Тест проверяет поведение,
  а не то, что «функция вызвалась»?
- На каждый баг, пойманный вживую, заведён тест, который бы его поймал (см. `TshClient.test.ts` —
  проверка `sanitizeTerminalReports`).

## 2. Живой прогон

Через скилл `run-xet-infra-gui` (Playwright-драйвер поверх собранного `out/`).

- Сценарий «как пользователь», а не только happy path: холодный старт → первое действие сразу
  (не дожидаясь статуса) → переключение вкладок → завершение сессии → повтор.
- Смотреть **не только скриншот**: скриншот покажет пустую панель, но не скажет почему. Буфер
  сессии целиком:
  ```
  eval window.api.invoke("app.bootstrap").then(b=>Promise.all(b.sessions.map(
    s=>window.api.invoke("session.snapshot",{id:s.id}))))
  ```
  Именно так нашлось, что в буфере логов лежат два запроса терминала и ничего больше.
- Логи main-процесса: `logs 40` в REPL драйвера — там видны дословные аргументы спавна.
- После прогона: `pkill -f 'xet-infra-gui/node_modules/electron'` — иначе single-instance lock
  сорвёт следующий запуск.

Отдельно проверить **закрытое окно**: приложение menu-bar, окно скрыто большую часть жизни.
Что оно делает в это время? Опрашивает сеть? Копит память?

## 3. Цена вызовов (то, что не видно в коде)

- Замерить реальный вызов: `time tsh kubectl get pods …`. Сколько секунд, сколько байт?
- Кто его вызывает и как часто: таймер в компоненте? каждое действие? трей? Сложить в
  «вызовов в минуту при обычной работе».
- Что происходит при **уходе и возврате на вкладку** — компонент перемонтировался и всё
  перезапросил? Данные должны жить в сторе, а не в стейте компонента.
- Есть ли: TTL-кэш, дедуп параллельных запросов, `force` для ручного обновления,
  **инвалидация по сигналу** (событие, а не таймер) там, где устаревание критично.
- Тяжёлый вызов на старте: он точно нужен до первого действия пользователя?

## 4. Слои, паттерны, дубли

- `core` без Electron, `renderer` без `@core/*` — это ловит eslint, но не ловит **дубль логики**,
  который появляется как раз из-за границы слоёв. Доменное решение считается один раз в ядре и
  едет в DTO (пример: «свежайший под» → `PodsResult.freshest`, а не повтор алгоритма в UI).
- Одинаковые константы/эвристики в двух файлах (списки маркеров, пороги, форматы) — свести.
- Новый сервис: у него одна ответственность? Он общается событиями/портами, а не лезет в чужие
  внутренности? Композиция — в `src/main/index.ts`, а не внутри ядра.
- Состояние, которое видят и окно, и трей, живёт **в одном месте** (владелец в main).

## 5. Лишнее

- Каждое новое публичное имя — `grep` по репозиторию: есть вызывающий? Нет — удалить.
  Так ушли `kubeLs`, `KubeClusterInfo`, RPC `kube.state` / `kube.login`.
- Фикстуры без тестов, поля конфига, которых никто не читает, «задел на будущее» — удалять.
- Комментарии: убрать те, что пересказывают код; проверить, что примеры в докстрингах не
  устарели (после смены фикстуры имя пода в примере жило ещё коммит).
- Мёртвое, унаследованное от прошлых этапов, — назвать вслух, но не удалять молча.

## 6. Данные и фикстуры

- Фикстура повторяет **форму** реального вывода? Придуманная форма воспроизводит то, что ты
  ожидаешь, а не то, что бывает: сверь с живым выводом, а несверенное помечай `⚠️` (NFR-7).
- Содержимое при этом выдуманное: имена кластеров, подов, контейнеров и пользователей из
  чьей-либо инфраструктуры в репозиторий не попадают (docs/README §5).
- Кейсы, которые не приходят в голову на пустом месте, — держи в наборе намеренно: sidecar в
  каждом поде, служебный контейнер **перед** приложением, поды в фазе `Succeeded`, соседний
  релиз свежее рабочего.
- Время в фикстурах: опорное «сейчас» должно быть позже всех таймстампов (иначе отрицательный
  age и тесты, «доказывающие» ерунду).

## 7. Обещания документации

- Пройтись по FR/US/NFR этапа в [01](01-requirements.md) и по [02](02-ux.md): что обещано, но
  не сделано? (Так нашёлся забытый в M2 prod-guard: US-14 и §5 требовали подтверждения перед

- Отклонение от [03](03-architecture.md) — новый ADR, а не молчаливое «сделал иначе».
- Roadmap: секция «проверено» с указанием **чем именно** проверено (живой кластер? фейк?) и
  секция «осталось сверить» — без приукрашивания.

## 8. Ошибки глазами пользователя

Пройти по списку отказов: нет сети, протух сертификат, нет пода, не тот кластер, таймаут,
непонятный exit-код. Для каждого:

- что видно в UI? (не «ничего не произошло» и не сырой stderr)
- мусор снят (ANSI, управляющие последовательности), текст читаемый;
- есть действие: кнопка «Перелогин», «Обновить», «Повторить в терминале»;
- ошибка не задвоена (баннер раздела + общий баннер) и не проглочена (`catch {}`).

## 9. Состояния, потоки, завершение

- FSM: из каждого состояния есть выход. Спросить себя: «что если процесс не напечатает вообще
  ничего / напечатает всё сразу / умрёт молча?»
- Потоки: пауза, backpressure, дедуп при восстановлении, порядок подписки и снапшота.
- Завершение: процесс убит, реестр очищен, сироты не остались (`ps aux | grep electron`),
  таймеры и подписки сняты в `return` из `useEffect`.

## 10. UX-мелочи, которые обычно забывают

- Пустое состояние ≠ состояние загрузки («нет подов под маской» вместо «запрашиваю…»).
- Кнопки задизейблены на время операции; двойной клик не плодит две сессии.
- Опасное (prod, необратимое) — с подтверждением; безопасное (чтение, логи) — без.
- Длинные списки: фильтр, осмысленная сортировка, счётчики, чтобы не листать сотни строк.
- Клавиатура: Enter в инпуте делает то же, что кнопка; фокус после открытия панели.
- Числа человеку: `26h`, `exit 0 · 2989 мс`, «обновлено 21:02» — а не сырые миллисекунды.

## 11. Безопасность

- Секреты не покидают main: не в renderer, не в логах, не в ring buffer, не в конфиге.
- Preload: канал добавлен в allowlist осознанно; на границе main — zod-схема запроса.
- Prod-действия отличимы визуально и требуют подтверждения (US-14).
- Автоматизация не логинится сама и не вводит реальные креды (см. `--with-creds` в скилле).

## Приложение: типовые ошибки этого проекта

| Симптом                                 | Причина                                                              | Что проверять впредь                                   |
|-----------------------------------------|----------------------------------------------------------------------|--------------------------------------------------------|
| Всё зелёное, вживую не работает         | фейковый CLI не воспроизводит реальный протокол                      | прогон на живом сервисе до отчёта о готовности         |
| Панель/таб пустые, состояние «работает» | процесс ждёт ответа, которого мы не даём (запросы терминала под PTY) | смотреть ring buffer, а не скриншот                    |
| Мусор `[31mERROR:` в UI                 | ANSI из stderr внешнего CLI                                          | `stripAnsi` на границе, фикстура реального stderr      |
| «Нужен перелогин» не предлагается       | регулярка под конкретную формулировку ошибки                         | набор паттернов + фикстуры живых сообщений             |
| Таб висит в «запускается»               | FSM ждёт события, которого для этого сценария не бывает              | перебрать сценарии «а если вывода не будет»            |
| UI тормозит на ровном месте             | тяжёлый вызов дёргается компонентом/таймером                         | замер стоимости + кэш + видимость окна                 |
| Дубль алгоритма в UI и ядре             | граница слоёв запрещает импорт — соблазн скопировать                 | считать в ядре, отдавать результат в DTO               |
| Код без вызывающих                      | «пригодится» / пункт плана выполнен буквально                        | grep на каждое новое публичное имя                     |
| Фикстура врёт                           | форма придумана, а не сверена с живым выводом                        | сверить форму, пометить ⚠️ несверенное                 |

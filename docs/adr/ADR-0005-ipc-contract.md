# ADR-0005: Типизированный IPC-контракт в shared, main как источник правды

**Статус**: принят (2026-07-29)

## Контекст

Три процесса Electron должны общаться безопасно и предсказуемо; renderer sandboxed и не
имеет Node. Основной риск — расползание строковых каналов и дублирование типов.

## Решение

1. Единственный источник контракта — `src/shared/ipc.ts`: имена каналов, типы
   запрос/ответ/событие, zod-схемы. Main регистрирует обработчики по контракту, preload
   генерирует `window.api` из него же.
2. Два вида взаимодействия: **RPC** (`ipcRenderer.invoke`, запрос-ответ) и **события**
   (`webContents.send`, потоки: `session/data`, `session/state`, `health/update`,
   `auth/required`, `task/progress`).
3. Renderer не содержит бизнес-логики и не хранит правду: zustand — проекция; при
   (пере)открытии окна — снапшот (`session.snapshot` + текущее состояние), далее — дельты
   событиями.
4. Обе стороны валидируют полезные нагрузки zod'ом; неизвестное отбрасывается с логом.
5. Потоковые данные батчатся в main (ADR-0002), события «дорогих» состояний коалесцируются.

## Последствия

- (+) Сессии переживают окно бесплатно (правда в main); UI перезапускается без потерь.
- (+) Контракт — одно место для ревью безопасности границы.
- (−) Каждый новый интерфейсный кусок требует правки контракта — намеренная точка трения.

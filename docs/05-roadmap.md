# 05 — Roadmap

Принцип порядка: **самые рискованные связки — первыми** (PTY+PATH+MFA-автоответ), полировка —
потом. Каждая фаза заканчивается проверяемым критерием «demo-able».

## M0 — Walking skeleton (снимаем главные риски) — ✅ выполнено 2026-07-29

Цель: доказать, что вся цепочка «Electron → node-pty → tsh → автоответ MFA → xterm» работает.

- [x] Scaffold: electron-vite + TS + React, каркас слоёв `core/main/preload/renderer/shared`, eslint-правило границ
- [x] ShellPathResolver (PATH из login-shell) + override пути tsh
- [x] NodePtyFactory + SessionManager (минимум: spawn, onData, write, exit; батчинг 12 мс, ring buffer)
- [x] xterm в окне (WebGL, fit), привязка к сессии через IPC-контракт v0
- [x] PromptPipeline: Password + Totp (секрет пока из env-переменных) + фикстурные тесты промптов
- [x] `tsh status --format=json` через ExecFileRunner + отображение TTL серта
- [x] Санитайзинг ввода в PTY: вырезание терминальных report-ответов xterm (CPR/DA/DSR/OSC)
  на auth-фазе — иначе они портят чтение пароля (см. ниже и docs/04 §7)
- [x] Дедуп восстановления xterm: watermark потока (`cursor`/`end` + `replaySlice`) — снапшот
  ring buffer и живые чанки не дублируются на гонке «подписка↔снапшот» (docs/04 §7)

**Критерий**: кнопка «Login» выполняет полный перелогин без единого нажатия клавиатуры;
`tsh status` показывает свежий `valid_until`.

Проверено вживую (Playwright `_electron` + реальный tsh): статус/отсчёт серта, PTY-спавн
login-сессии, exit 0 → авто-refresh статуса, вывод в xterm, ручной фолбэк-баннер.
Автоответ пароль/OTP покрыт unit-тестами на дословных фикстурах промптов; живой прогон —
при протухшем серте с выставленными `XET_TELEPORT_*`.
Грабли, пойманные на живом прогоне:

- npm теряет exec-бит `spawn-helper` у node-pty (`posix_spawnp failed`) — починено `postinstall`.
- **Порча пароля терминальными авто-ответами** (не косметика, как думалось): tsh при старте
  запрашивает у терминала фон (OSC 11) и позицию курсора (DSR), xterm авто-отвечает через
  `onData`, а renderer слал это в PTY; из-за задержки Electron ответы попадали в stdin поверх
  читаемого пароля → `invalid credentials`, MFA-шаг не наступал. Подтверждено на
  `@xterm/headless`. Фикс: `stripTerminalReports` в `SessionManager.write` на auth-сессиях
  (флаг `sanitizeTerminalReports`), ответы пайплайна (пароль/OTP) идут мимо фильтра.

## M1 — DB-прокси и супервизия — ✅ выполнено 2026-07-29 (частично проверено вживую)

- [x] Пресеты прокси из конфига (4 шт., секция `db`), FSM сессии целиком (healthy/degraded;
  `restarting` живёт на уровне ПРОКСИ — каждый рестарт это новый PTY, см. core/domain/proxy.ts)
- [x] Батчинг 12 мс + backpressure: ack — абсолютный watermark потока (`session.ack {upTo}`),
  pause > 512K неподтверждённого, resume < 128K; выключается при закрытом окне
- [x] HealthMonitor: локальный отсчёт серта + редкий `tsh status` (5 мин), powerMonitor.resume;
  TCP-probe туннелей — у ProxySupervisor (единственный владелец состояния прокси)
- [x] ProxySupervisor: backoff-рестарты (1→30 с, лимит 5, сброс после 30 с стабильности),
  `restartOnRelogin` — каскад по событию AuthService.loggedIn
- [x] Menu bar: emoji-статус (🟢🟡🔴⚪, template-иконки — M4) + нативное меню с тумблерами;
  single instance; окно закрывается — приложение живёт в трее; before-quit гасит всех
- [x] Стратегия портов `shared`: конфликт пресетов → подтверждение переключения (force);
  порт занят чужим → отказ + вывод `lsof`
- [x] Keychain (safeStorage → userData/secrets.bin) для пароля и TOTP-секрета, env — dev-фолбэк;
  мастер TOTP-девайса (`tsh mfa add`, MfaEnrollService) — секрет парсится из вывода,
  подтверждающий код авто; ⚠️ фикстуры промптов мастера реконструированы, вживую НЕ сверены
- [x] XET_TELEPORT_* вырезаются из env дочерних процессов (stripCredEnv); завершённые сессии
  удаляются из реестра (dispose таба, рестарты прокси, повторный login)

**Критерий**: тумблер dev → зелёный; `kill -9` процесса прокси → сам поднялся; серт протух →
баннер, один клик — перелогин, прокси перезапустились; закрыл/открыл окно — терминал с историей.

Проверено вживую (Playwright + реальный tsh, серт живой): тумблер dev спавнит дословно
`tsh proxy db --port=6432 --db-user=app --db-name=dev --tunnel --mfa-mode=otp dev-postgres`,
состояния «проверка порта…» честные, выключение — SIGTERM → exit 0, реестр чистится; панель
кредов и мастер отображаются. Юнитами покрыто: happy-path прокси (OTP→probe→healthy),
backoff/лимит, конфликт shared-порта, busy-port+lsof, restartMarked, backpressure, health-фронты.
Осталось проверить вживую (нужны креды/действия пользователя): полный цикл тумблера до
healthy с per-session MFA, каскад после перелогина, мастер TOTP-девайса (сверить фикстуры).

## M2 — Kubernetes — ✅ выполнено 2026-08-01 (проверено на живом dev-кластере)

- [x] TshClient: `kube login` (с `--mfa-mode=otp` и авто-повтором без флага, если сборка tsh его
  не знает) + `kubectl get pods -o json` с loose-zod DTO
- [x] Экран «Поды»: таблица (имя/ready/статус/рестарты/age в формате kubectl), группировка по
  workload'ам + «прочее», бейдж «свежий», фильтр по имени и «только Running», ручной выбор
- [x] PodSelector + containerAutoDiscover (sidecar'ы отсеиваются) + тесты на реальной фикстуре
- [x] KubeService — владелец выбранного окружения (одного на окно и трей): прозрачный
  `kube login` при несовпадении кластера, сериализованный очередью
- [x] Кэш списка подов (TTL 15 с + дедуп параллельных запросов + сброс по сигналу «сессия
  умерла»): переключение вкладок и быстрые действия не платят по ~2 с за `get pods`;
  в renderer список живёт в сторе, автообновление — только при видимом окне
- [x] «Bash → workload» из бара, таблицы подов и трея; реконнект к свежему поду для мёртвой
  kube-сессии (привязка сессия→под живёт в KubeService, в renderer — зеркалом)
- [x] Логи `--tail/--follow` PTY-сессией ([ADR-0007](adr/ADR-0007-kube-streams-via-pty.md)):
  пауза потока (`session.setPaused`, сильнее backpressure) и поиск по буферу xterm
- [x] One-shot команда с панелью вывода; при per-session MFA — фолбэк «в терминале» (PTY)
- [x] Быстрые действия и выбор окружения в popover трея
- [x] Prod-guard (US-14): bash и команды на prod — с подтверждением (в окне и в трее); логи
  read-only и не спрашивают
- [x] FSM: сессия без промптов уходит `spawning → running` по первому выводу (раньше kube-табы
  вечно висели в «запускается»)

**Критерий**: из menu bar до bash в свежайшем поде workload'а — 2 клика; логи стримятся без
подвисаний UI при `--follow` на шумном поде. — выполнено вживую.

Проверено на живом dev-кластере (Playwright + реальный tsh, серт живой): таблица подов с
группировкой по workload'ам и «прочим» и честным age; быстрое действие «Bash → workload»
разворачивается в дословный `tsh kubectl exec -it <свежайший под> -n <namespace> -c
<контейнер> -- bash` и даёт живой промпт shell'а; логи с `--tail=500 --follow` (десятки КБ за
первые секунды, пауза и поиск работают); one-shot команда → `exit 0` с выводом панелью;
реконнект после завершения сессии поднимает новый таб; список подов не перезапрашивается при
переключении вкладок. `tsh kube login --mfa-mode=otp` этой сборкой tsh поддержан, per-session
MFA на dev не требовалась.

Поймано вживую и починено (то, чего не показал ни один тест на фейковом tsh):

1. `kubectl logs`/`exec` под PTY молчали: tsh опрашивает терминал (`ESC]11;?`, `ESC[6n`) и ждёт
   ответа, а фильтр `sanitizeTerminalReports` (защита stdin auth-сессий) эти ответы срезал.
2. `ERROR: ssh: cert has expired` приезжал в UI с ANSI-раскраской и не распознавался как
   «нужен перелогин» (фикстура `KUBE_LOGIN_EXPIRED_STDERR`).
3. Kube-табы висели в «запускается»: FSM не выходила из `spawning` без промптов.
4. Холодный старт делал лишний `kube login` в уже активный кластер: действие обгоняло первый
   `tsh status`, а пустой кэш статуса читался как «контекста нет».

Осталось сверить вживую: переключение на stage/prod (нужен логин в эти кластеры) и поведение
`logs`/`exec` там, где кластерная политика требует per-session MFA.

## M2.1 — Отвязка от конкретной инфраструктуры — ✅ выполнено 2026-08-01

Не фича, а вычистка: до этого окружение автора было зашито в дефолты схемы, фикстуры, тесты
и документацию, а схема конфига жила в `main` вторым описанием тех же типов из `core`.

- [x] Схема конфига переехала в core: секции модуля (`modules/teleport/config.ts`) + сборка
  (`config/schema.ts`); типы выводятся из неё через `z.infer`, дублей нет
- [x] Порт `ConfigStore` + `ConfigService` (загрузка, валидация, сохранение) в core;
  fs и разрешение пути (`XET_CONFIG_PATH`) — адаптером в main; `main/config.ts` удалён
- [x] Дефолты пустые: приложение стартует без конфига и показывает онбординг (Login заблокирован,
  панели прокси и kube скрыты); невалидный файл не роняет старт
- [x] RPC `config.get/save/importFile/exportFile/relaunch` + вкладка «Конфиг» в настройках:
  редактор текстом, импорт/экспорт шаблона, перезапуск для применения
- [x] `config.example.json` в репозитории; личные значения и замеры окружения — в
  `local-artifacts/` (в `.gitignore`)
- [x] Фикстуры и тесты синтетические: сохранены только неудобные для кода свойства (прокси перед
  приложением в spec, коллизии префиксов, `Succeeded`-поды), а имена, топология и состав
  контейнеров выдуманы
- [x] Документация и git-история переписаны: реальных имён кластеров, подов и пользователей
  в репозитории нет — [ADR-0008](adr/ADR-0008-config-and-profiles.md)

**Критерий**: `grep -ri` по репозиторию не находит ни одного имени из чужой инфраструктуры,
а приложение с пустым конфигом стартует и объясняет, что делать. — выполнено.

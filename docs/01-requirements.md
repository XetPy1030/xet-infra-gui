# 01 — Требования

## 1. Видение

Одно приложение в menu bar мака, которое сводит ежедневную инфраструктурную рутину к
«одному клику или хоткею»: поднять DB-прокси, зайти в контейнер, посмотреть логи, выполнить
SQL — без ручного набора длинных `tsh`-команд, без ручного ввода пароля и OTP, с постоянно
видимым статусом (жив ли прокси, не протух ли сертификат).

Долгосрочно — персональный «хаб»: не только работа с Teleport, но и быстрые ссылки
(Grafana с фильтрами), календарь/напоминалки, пространства. Поэтому ядро проектируется
модульным с первого дня, хотя реализуется сейчас только модуль Teleport.

## 2. Контекст

Приложение ничего не знает про конкретную инфраструктуру: прокси, пользователь, окружения,
namespace, workload'ы и db-пресеты приходят из конфига (§4.7, [04 §2](04-tsh-integration.md#2-модель-конфигурации)).
В коде и фикстурах нет ни одного реального имени — от них зависит только содержимое
конфига пользователя.

Форма инфраструктуры, под которую приложение спроектировано:

- Доступ ко всему — через один Teleport-прокси, один пользователь, пароль + 2FA.
  Кластер может предпочитать webauthn, поэтому автоматизации нужен TOTP.
- Несколько окружений (`dev` / `stage` / `prod`), у каждого — свой k8s-кластер;
  db-туннели есть не обязательно во всех.
- В namespace живёт несколько логических служб («workload'ов»), имена подов которых
  меняются от релиза к релизу, поэтому сопоставление идёт по маскам.
- Рабочее место: macOS (Apple Silicon), zsh, `tsh` в PATH, psql/pg_dump из Homebrew.

Личные значения автора (кластер, маски, пресеты) в репозиторий не попадают — они лежат
в `local-artifacts/` и подтягиваются через `XET_CONFIG_PATH` либо импортом шаблона.

## 4. Функциональные требования

### 4.1 Аутентификация (Auth)

- **FR-A1**: хранение email/пароля и TOTP-секрета в macOS Keychain (Electron `safeStorage`); ввод — через UI настроек
  при первом запуске.
- **FR-A2**: источник кредов — за интерфейсом `CredentialStore`; сейчас локальный Keychain, в будущем — удалённый API (
  другой бэкенд-проект). Смена источника не трогает остальной код.
- **FR-A3**: автоматический ответ на промпты `Enter password for Teleport user …:` и `Enter an OTP code from a device:`
  в любой PTY-сессии; при отсутствии сохранённых кредов или неудаче — фолбэк на ручной ввод в UI.
- **FR-A4**: регистрация собственного TOTP-девайса приложения через `tsh mfa add --type TOTP` (мастер в настройках);
  генерация кодов — `otplib`.
- **FR-A5**: отображение срока действия сертификата (`valid_until` из `tsh status --format=json`) с обратным отсчётом;
  предупреждение заранее (например, за 30 минут).
- **FR-A6**: кнопка/действие «Перелогин» (`tsh login --proxy=… --user=…`), после успеха — автоматический перезапуск
  помеченных для этого сессий.

### 4.2 DB-прокси (DbProxy)

- **FR-D1**: конфигурируемые пресеты прокси (сколько угодно, каждый со своим окружением) →
  `tsh proxy db --port=<p> --db-user=<user> --db-name=<db> --tunnel <tunnel> --mfa-mode=otp`.
- **FR-D2**: тумблер вкл/выкл на каждый пресет в menu bar и в окне.
- **FR-D3**: health-check активного прокси: процесс жив + TCP-connect на локальный порт + (опционально) `SELECT 1` через
  драйвер; статусы: `starting / healthy / degraded / dead`.
- **FR-D4**: политика портов: `shared` — все пресеты на одном локальном порту (совместимость с уже настроенными
  клиентами БД), включение прокси другого окружения предлагает переключить; опционально режим «порт на окружение».
- **FR-D5**: supervision: упавший прокси перезапускается с экспоненциальным backoff и лимитом попыток; причина падения
  видна в UI.
- **FR-D6**: занятый порт (EADDRINUSE) — понятная ошибка с указанием, кем занят, и предложением действий.

### 4.3 Kubernetes (Kube)

- **FR-K1**: переключение активного кластера: `tsh kube login {dev,stage,prod}-k8s-cluster`; текущий кластер всегда
  виден.
- **FR-K2**: список подов namespace из конфига: `tsh kubectl get pods -o json` (+ фильтр Running); колонки
  name/ready/status/restarts/age; группировка по workload; авто-обновление по запросу/таймеру.
- **FR-K3**: определение «свежайшего» пода workload'а: маска префикса + `phase==Running` + все контейнеры ready →
  максимальный `startTime`.
- **FR-K4**: «Bash в контейнер»: PTY-сессия `tsh kubectl exec -it <pod> -n <namespace> -c <container> -- bash` для
  любого workload'а из конфига; контейнер берётся оттуда же, с автообнаружением по `spec.containers[].name`.
- **FR-K5**: one-shot команда в контейнере: `tsh kubectl exec <pod> … -- sh -lc '<cmd>'` (без `-it`), вывод в панель
  результата, с таймаутом.
- **FR-K6**: логи: `tsh kubectl logs <pod> -c <container> [--follow --tail=N]`; follow-поток с батчингом, пауза,
  автоскролл, поиск.
- **FR-K7**: маски имён подов конфигурируемы (имена релизов могут меняться).

### 4.4 Сессии и терминал (Sessions)

- **FR-S1**: интегрированный терминал `@xterm/xterm` (WebGL) для всех интерактивных сессий: login, proxy (вывод), exec
  bash, psql.
- **FR-S2**: сессии живут в main-процессе; закрытие окна их не убивает (US-13). Полный выход из приложения корректно
  гасит все дочерние процессы.
- **FR-S3**: ring buffer вывода на сессию (по умолчанию 256 КБ) для восстановления содержимого терминала при
  переоткрытии окна.
- **FR-S4**: жизненный цикл сессии — явная машина состояний; каждое состояние отображается в UI.
- **FR-S5**: пропускная способность: батчинг PTY→UI (8–16 мс), backpressure (pause/resume PTY при отставании рендера).

### 4.5 SQL-консоль (Sql)

- **FR-Q1**: выполнение запросов через драйвер `pg` в поднятый туннель (localhost:port, `dbUser` пресета); результат —
  таблица; ошибки — читаемо.
- **FR-Q2**: история запросов (локально, с привязкой к окружению); повтор из истории.
- **FR-Q3**: защита: `statement_timeout` по умолчанию; на пресетах с `dangerous` мутирующий запрос требует
  подтверждения (эвристика по тексту), а неподтверждённый выполняется в read-only транзакции — ошибка эвристики
  тогда стоит отказа сервера, а не записи в боевую базу ([ADR-0009](adr/ADR-0009-sql-console.md)).
- **FR-Q4**: кнопка «открыть psql в терминале» (интегрированная PTY-сессия).
- **FR-Q5**: пресеты `pg_dump` (команда с подстановками `{port}`/`{dbName}`/`{file}`) с выбором файла назначения и
  индикацией выполнения.

### 4.6 UI/UX (подробно — [02-ux.md](02-ux.md))

- **FR-U1**: menu bar: иконка-статус (агрегат: сертификат + прокси), popover с тумблерами и быстрыми действиями.
- **FR-U2**: главное окно: sidebar (окружения/разделы) + табы сессий + статус-бар.
- **FR-U3**: палитра команд ⌘K поверх реестра действий (Command pattern) — единая точка входа для всего.
- **FR-U4**: глобальный хоткей показа/скрытия окна (настраиваемый); внутренние хоткеи на частые действия.
- **FR-U5**: индикация загрузки на каждой операции >200 мс (US-12); длинные операции — в статус-баре со спиннером.
- **FR-U6**: prod-окружение маркируется красным; мутирующие действия на prod — с подтверждением (US-14).

### 4.7 Настройки (Settings)

- **FR-C1**: конфиг окружений/workload'ов/пресетов — JSON в userData, редактируемый и через UI, и как файл; схема
  валидируется (zod), пример — `config.example.json`
  и [04-tsh-integration.md](04-tsh-integration.md#2-модель-конфигурации).
- **FR-C3**: конфиг переносится между машинами: импорт/экспорт файла-шаблона из UI и переменная `XET_CONFIG_PATH` для
  запуска на произвольном файле. Пустой конфиг — не ошибка: приложение стартует и показывает онбординг.
- **FR-C2**: first-run wizard: проверка `tsh` в PATH → креды → TOTP-девайс → тестовый логин.
- **FR-C3**: переопределение пути к `tsh` и локальных портов.

## 5. Нефункциональные требования

- **NFR-1 Безопасность**: секреты только в Keychain (`safeStorage`), никогда в renderer-процессе, конфиг-файлах, логах
  приложения и ring buffer'ах не маскированными; OTP генерируется в main и пишется напрямую в PTY.
  `contextIsolation: true`, `nodeIntegration: false`, sandbox для renderer. Никакой телеметрии.
- **NFR-2 Надёжность**: supervision всех дочерних процессов; ни одного осиротевшего `tsh` после выхода; восстановление
  после сна/смены сети (powerMonitor → внеочередной health-check).
- **NFR-3 Производительность**: поток логов `--follow` не подвешивает UI (батчинг + WebGL + backpressure); старт
  приложения < 2 с до работоспособного menu bar.
- **NFR-4 Кроссплатформенность**: core и модули не содержат платформенных предположений; платформенное (
  Keychain/DPAPI/libsecret, трей, хоткеи, PATH-резолв) — за интерфейсами-адаптерами. Сейчас реализуется только macOS.
- **NFR-5 Расширяемость**: новые домены (Grafana, календарь) добавляются как модули с contribution points, без правок
  ядра ([ADR-0006](adr/ADR-0006-module-system.md)).
- **NFR-6 Тестируемость**: core тестируется без Electron (vitest); детекторы промптов — на фикстурах реальных выводов
  `tsh`; интеграционные тесты — с фейковым `tsh`-скриптом.
- **NFR-7 Обновляемость знаний о tsh**: всё специфичное для версии Teleport (тексты промптов, форматы) — изолировано и
  покрыто фикстурами, чтобы обновление кластера ломало тесты, а не пользователя.

## 7. Явно не делаем

- Управление ресурсами k8s за пределами: список/exec/логи (никаких apply/delete/scale).
- Мульти-кластерный Teleport (профиль один).
- Общий терминал-эмулятор «на каждый день» — терминал только для сессий приложения.
- Синхронизация настроек между машинами (до появления удалённого API кредов).

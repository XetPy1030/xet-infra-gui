# xet-infra-gui — документация

Персональный «инфраструктурный хаб» для macOS (в перспективе — кроссплатформенный): быстрые
шорткаты и GUI поверх ежедневной работы с Teleport (`tsh`) — DB-прокси, Kubernetes, логи, SQL.
Первый домен — работа (Teleport); архитектура закладывается под будущие домены
(Grafana-ссылки, календарь/напоминалки, пространства). Ничего специфичного для конкретной
инфраструктуры в репозитории нет: кластер, namespace, workload'ы и db-пресеты задаются
конфигом ([04 §2](04-tsh-integration.md#2-модель-конфигурации)).

## Ключевые решения (кратко)

- **Стек**: Electron 43 + TypeScript + electron-vite + React, `node-pty` (N-API) + `@xterm/xterm` 6 — [ADR-0001](adr/ADR-0001-electron-stack.md), [ADR-0002](adr/ADR-0002-pty-terminal.md)
- **Форм-фактор**: menu-bar-приложение с полноценным окном; сессии живут в фоне независимо от окна
- **Секреты**: пароль и TOTP-секрет — в macOS Keychain через Electron `safeStorage`; у приложения свой TOTP-девайс в Teleport, OTP-коды подставляются автоматически — [ADR-0003](adr/ADR-0003-secrets-and-totp.md)
- **Ядро**: гексагональная архитектура (ports & adapters), core не зависит от Electron; Command / FSM / Supervisor / Chain of Responsibility — [ADR-0004](adr/ADR-0004-core-patterns.md)
- **IPC**: типизированный контракт в `src/shared`, вся бизнес-логика в main-процессе — [ADR-0005](adr/ADR-0005-ipc-contract.md)
- **Расширяемость**: модульная система с contribution points; Teleport — первый модуль — [ADR-0006](adr/ADR-0006-module-system.md)
- **Kube-потоки**: логи и `exec -it` — PTY-сессии (один механизм доставки + переживают MFA), one-shot — exec-канал — [ADR-0007](adr/ADR-0007-kube-streams-via-pty.md)
- **Конфиг**: вся специфика инфраструктуры — только в конфиге (схема в core, файл через порт, импорт/экспорт шаблона, `XET_CONFIG_PATH`); дефолты пустые — [ADR-0008](adr/ADR-0008-config-and-profiles.md)
- **SQL**: драйвер `pg` в туннель, соединение на один запрос (общий порт ведёт в разные базы), боевая база — read-only транзакция вместо доверия эвристике, дампы — PTY-сессией — [ADR-0009](adr/ADR-0009-sql-console.md)

## Правила ведения документации

1. Каждое значимое архитектурное решение — новый ADR (формат: Статус / Контекст / Решение / Последствия). ADR не редактируются задним числом — устаревший помечается `Superseded by ADR-XXXX`.
2. Требования (01) и roadmap (05) — живые документы, обновляются при изменении планов.
3. Этап не считается готовым, пока не пройден [06-final-check](06-final-check.md) — и его итог
   (что проверено чем, что осталось) записан в roadmap.
4. Фактура про `tsh` (04) проверяется против конкретной версии Teleport (сейчас: client 17.0.4, server 17.0.1) — при обновлении кластера перепроверить промпты и JSON-форматы.
5. В репозиторий не попадает чужая инфраструктура — ни имена (кластеры, поды, контейнеры,
   namespace'ы, роли, пользователи), ни её устройство (схема именования релизов, состав
   sidecar'ов, набор компонентов, замеры размеров и таймингов). Фикстуры синтетические:
   от реального вывода в них форма полей, а не содержимое. Личные значения и замеры живут
   в `local-artifacts/` (в `.gitignore`).

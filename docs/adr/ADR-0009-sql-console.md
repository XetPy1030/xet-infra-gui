# ADR-0009: SQL-консоль поверх туннеля DB-прокси

**Статус**: принят (2026-08-02)

## Контекст

M3 добавляет выполнение запросов к базам, к которым приложение и так держит туннели
(`tsh proxy db --tunnel`). Своего SQL у tsh нет — `tsh db connect` это обёртка над psql,
интерактив. Значит, нужен собственный клиент, и с ним три неочевидных вопроса:

1. **Общий локальный порт.** При стратегии портов `shared` все пресеты садятся на один и тот
   же `127.0.0.1:<port>`, а включение другого пресета выключает предыдущий. Адрес соединения
   при этом не меняется — меняется база на том конце.
2. **Боевая база.** «Подтверждение мутирующих запросов» (FR-Q3) упирается в то, что определить
   мутирующий запрос текстом — эвристика: `with … delete … returning`, `explain analyze`,
   `select nextval()`, вызов процедуры.
3. **Дампы.** `pg_dump` — внешняя команда с редиректом в файл, у которой нет ни процентов, ни
   структурированного вывода.

## Решение

**Соединение живёт ровно один запрос.** Порт `SqlDriver` (адаптер `PgSqlDriver` на `pg`)
открывает соединение, ставит `statement_timeout`, выполняет запрос и закрывается.
Переиспользованное соединение после переключения тумблера молча отвечало бы из прошлой базы —
худший вид ошибки: правдоподобный результат не из той среды. Цена (локальный TCP-connect через
уже поднятый туннель) на порядок меньше самого запроса.

**На `dangerous`-пресете запрос без подтверждения выполняется в `BEGIN READ ONLY`.** Эвристика
`classifyQuery` решает только одно — спрашивать ли подтверждение; если она ошиблась и записью
оказалось то, что выглядело чтением, запрос отобьёт сам PostgreSQL (`25006`). Подтверждённый
запрос идёт без обёртки. Значения приводятся к строкам в адаптере: в таблицу и в IPC всё равно
поедет текст, а `Date`/`Buffer`/`json` по дороге превратились бы в `[object Object]`.

**Дамп — PTY-сессия `sh -lc '<команда>'`** (продолжение [ADR-0007](ADR-0007-kube-streams-via-pty.md)):
шаблон из конфига разворачивается подстановками выбранного туннеля, редирект и пайпы работают
как в терминале, вывод и код возврата видны обычным табом. Прогресс — рост файла на диске
(порт `FileStat`), по завершении — системное уведомление.

**`SELECT 1` отдан ProxySupervisor'у** как расширенный health-check (FR-D3): открытый локальный
порт не значит рабочую базу. Проверка обязательна на пути к первой готовности и повторяется раз
в минуту — чаще незачем, это соединение через Teleport, а не локальный connect. Зависимость
ставится сеттером (`setSqlProbe`), потому что SqlService спрашивает у супервизора состояние
прокси: через конструкторы пара была бы циклической.

Попутно: порт `ConfigStore` обобщён до `TextStore` (тот же файл-с-текстом, второй потребитель —
история запросов), адаптер — `FileTextStore`; в [ADR-0008](ADR-0008-config-and-profiles.md) он
упоминается прежним именем `FileConfigStore`.

## Последствия

- (+) Результат всегда из той базы, которая выбрана: ошибиться средой невозможно by construction.
- (+) Защита боевой базы держится на сервере, а не на регулярке; эвристика отвечает только за
  удобство диалога.
- (+) Дампы, логи и exec — один механизм сессий: ring buffer, backpressure, живой таб.
- (−) Соединение на запрос = нет сессионного состояния: временные таблицы, `set` и явные
  транзакции между запросами не переживают. Кому нужно — «psql в терминале».
- (−) История хранит **тексты запросов** в открытом виде (`<userData>/sql-history.json`) — там
  могут оказаться персональные данные из условий. Отключается `sql.historyLimit: 0`.
- (−) `pg` — первая рантайм-зависимость приложения помимо `node-pty`/`otplib`/`zod`.

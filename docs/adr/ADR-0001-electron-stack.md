# ADR-0001: Electron + TypeScript + electron-vite + React

**Статус**: принят (2026-07-29)

## Контекст

Нужно десктоп-приложение для macOS (в будущем Linux/Windows) с полноценным терминальным
виджетом, menu bar, глобальными хоткеями и фоновыми долгоживущими процессами. Кандидаты:
Electron, Tauri, нативный Swift/AppKit.

## Решение

Electron 43 + TypeScript + electron-vite 5 + React в renderer, electron-builder для пакетов.

Причины:
- `node-pty` + `@xterm/xterm` — фактические стандарты терминальной связки (родом из VS Code),
  покрывают задачу целиком; в Tauri терминальный стек пришлось бы собирать из более сырых кусков,
  а рендеринг зависел бы от системного WebView (WebKitGTK на Linux заметно слабее).
- Один Chromium на всех платформах — терминал выглядит и ведёт себя одинаково.
- Референсы открыты: VS Code, Hyper, Tabby — решения любых проблем связки подсмотриваются.
- Скорость разработки для одного человека: один язык на ядро и UI, DevTools, HMR.

React (а не Svelte): максимум готовых рецептов для Electron+xterm+zustand, проще
переиспользовать компоненты. Zustand для UI-состояния; вся бизнес-логика — в main.

## Последствия

- (−) ~120–250 МБ дистрибутив, сотни МБ RAM — принимаем для инструмента ежедневного использования.
- (−) Ядро на Node без гарантий Rust/Go — компенсируем строгим TS, FSM и тестами core.
- (−) Логика ядра не переносится в гипотетический нативный клиент — принимаем; core отделён
  от Electron, что оставляет путь к CLI/другому хосту на Node.
- (+) Наиболее короткий путь к M0 и наименьший риск по терминальной части.

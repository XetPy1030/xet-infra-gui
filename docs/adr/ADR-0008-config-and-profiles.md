# ADR-0008: Конфиг как единственный носитель специфики инфраструктуры

**Статус**: принят (2026-08-01)

## Контекст

Первая версия приложения знала окружение автора наизусть: прокси, пользователь, namespace,
маски подов и db-пресеты были дефолтами zod-схемы в `main/config.ts`. Это давало три беды:

1. Репозиторий нельзя показать никому, а имена из чужой инфраструктуры лежат в фикстурах,
   тестах и документации — и остаются в истории git.
2. Схема жила в `main`, а те же поля вторым описанием — интерфейсами в `core`. Две правды,
   которые расходятся молча.
3. Переезд на другую машину или второй кластер означал правку исходников.

## Решение

**Конфиг — единственное место, где живёт специфика инфраструктуры.** В коде нейтральные
имена, дефолты пустые, приложение без конфига стартует и показывает онбординг.

Слои:

| Слой | Кто | Что делает |
|---|---|---|
| `core/modules/teleport/config.ts` | модуль | zod-схемы своих секций (teleport / db / kube) |
| `core/config/schema.ts` | ядро | сборка `appConfigSchema`, `parseConfig`, `isConfigured` |
| `core/ports/ConfigStore.ts` | порт | чтение/запись **сырого текста**, про схему не знает |
| `core/services/ConfigService.ts` | сервис | загрузка, валидация, сохранение, состояние для UI |
| `main/adapters/FileConfigStore.ts` | адаптер | fs + разрешение пути (`XET_CONFIG_PATH`) |
| `main/ipc/configBridge.ts` | main | диалоги импорта/экспорта и перезапуск (Electron) |

Схема — источник и типов: `DbProxyPreset`, `KubeWorkload`, `KubeConfig` выводятся через
`z.infer`, второго описания той же формы нет.

Пути доставки конфига:

- `<userData>/config.json` — обычный запуск, создаётся пустым при первом старте;
- `XET_CONFIG_PATH=…` — запуск на произвольном файле (личные артефакты, второй кластер);
- импорт/экспорт файла-шаблона из «Настроек» — перенос между машинами;
- `config.example.json` в репозитории — нейтральный образец формы.

Личные значения автора и замеры живого окружения лежат в `local-artifacts/` (в `.gitignore`).

**Сохранение не применяется на лету.** `ProxySupervisor` получает пресеты при сборке,
`KubeService` — геттером, `TshClient` — резолвленный `tshPath`: частичный горячий подхват дал
бы половину приложения на старых настройках. `ConfigService.get()` до конца процесса отдаёт
стартовый конфиг, а UI после записи предлагает перезапуск.

## Последствия

- (+) Репозиторий не привязан ни к какой организации; фикстуры обезличены, структура сохранена.
- (+) Одна правда о форме конфига; расхождение схемы и типов невозможно by construction.
- (+) Новый модуль добавляет свою секцию, не трогая ядро (продолжение [ADR-0006](ADR-0006-module-system.md)).
- (−) Приложение из коробки ничего не умеет — первый запуск требует конфига.
- (−) Применение правок стоит перезапуска; горячий reload — отдельная задача, если понадобится.

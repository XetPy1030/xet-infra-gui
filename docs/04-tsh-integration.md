# 04 — Интеграция с tsh (Teleport)

Проверено против клиента `tsh` **17.0.4** и сервера **17.0.1**. Предпосылки, на которых стоит
автоматизация (сверить на своём кластере):

- MFA включён, а предпочтительный способ может быть `webauthn` ⇒ режим задаём всегда явно:
  `--mfa-mode=otp`;
- `private_key_policy: none` — при требовании аппаратного ключа PTY-автоматизация невозможна;
- TTL сессии задаёт кластер, приложение читает срок из `tsh status` и само ничего не
  предполагает.

Примеры ниже синтетические: форма вывода настоящая, содержимое выдумано (docs/README §5).

## 1. Два канала работы с tsh

| Канал               | Когда                                                                                                       | Механика                                 |
|---------------------|-------------------------------------------------------------------------------------------------------------|------------------------------------------|
| **PTY** (node-pty)  | интерактив и всё, что может спросить пароль/OTP: `login`, `proxy db`, `kubectl exec -it`, `psql`, `mfa add` | поток через PromptPipeline, FSM          |
| **exec** (execFile) | структурированные запросы: `status`, `db ls`, `kube ls`, `get pods`, one-shot exec, logs                    | буферизация, таймаут, `JSON.parse` + zod |

Правило: если команда *может* запросить MFA — она идёт через PTY. Замечание: exec-каналу
тоже нужен обработчик ошибки «нужен релогин» (см. §6).

## 2. Модель конфигурации

Приложение не содержит настроек конкретной инфраструктуры: из коробки конфиг пуст
(ни прокси, ни namespace'а, ни пресетов), и UI показывает онбординг. Всё специфичное
приходит из файла.

**Откуда берётся файл** (`ConfigService` + порт `ConfigStore`):

| Способ                              | Когда                                                |
|-------------------------------------|------------------------------------------------------|
| `<userData>/config.json`            | обычный запуск; создаётся пустым при первом старте   |
| `XET_CONFIG_PATH=/путь/config.json` | dev-запуск на личных артефактах, вторая конфигурация |
| «Настройки → Конфиг»                | правка текстом, импорт и экспорт файла-шаблона       |

Шаблон с нейтральными значениями лежит в репозитории — `config.example.json`.

Схема (zod) — `core/modules/teleport/config.ts`, сборка — `core/config/schema.ts`. Она же
источник типов: `KubeWorkload`, `DbProxyPreset` и прочие выводятся через `z.infer`, второго
описания той же формы в проекте нет.

```jsonc
{
  "teleport": {
    "proxy": "teleport.example.com:443",
    "user": "user@example.com",
    "cluster": "",                      // пусто = хост из proxy
    "tshPath": null,                    // null = автоопределение через login-shell
    "mfaMode": "otp"
  },
  "db": {
    "portStrategy": "shared",           // "shared" (один порт на всех) | "perEnv"
    "presets": [
      { "id": "db-dev",  "env": "dev",  "tunnel": "dev-postgres",  "dbUser": "app", "dbName": "dev",  "port": 6432 },
      { "id": "db-prod", "env": "prod", "tunnel": "prod-postgres", "dbUser": "app", "dbName": "prod", "port": 6432, "dangerous": true }
    ]
  },
  "kube": {
    "namespace": "apps",
    "clusters": { "dev": "dev-k8s-cluster", "stage": "stage-k8s-cluster", "prod": "prod-k8s-cluster" },
    "workloads": [
      { "id": "api",  "title": "api",  "podPrefix": "api-web-", "container": "api" },
      { "id": "auth", "title": "auth", "podPrefix": "auth-web-",
        "podExclude": ["-worker-", "-cron-"],
        "container": "auth", "containerAutoDiscover": true }
    ],
    "logsTail": 500
  },
  "sql": {
    "statementTimeoutMs": 30000,        // 0 = не выставлять
    "maxRows": 1000,                    // сколько строк дотягиваем в таблицу
    "historyLimit": 200,                // 0 = не вести историю
    "psqlPath": "psql",                 // клиент для «psql в терминале»
    "dumpPresets": [
      { "id": "dump", "title": "pg_dump",
        // идёт в `sh -lc`, поэтому редирект и пайпы работают как в терминале
        "command": "pg_dump -U {dbUser} -h 127.0.0.1 -p {port} {dbName} > {file}",
        "defaultFile": "{dbName}-{date}.sql" }
    ]
  }
}
```

Пресеты дампа не привязаны к конкретной базе: шаблон разворачивается подстановками того
туннеля, который выбран в консоли, — один пресет годится и для dev, и для stage.

Имена подов меняются от релиза к релизу → сопоставление по **префиксу** + исключениям, не по
точному имени. Контейнер: значение из конфига, а при `containerAutoDiscover` — сверка со
`spec.containers[].name` пода (если точного совпадения нет — выбор наиболее похожего
не-sidecar-контейнера, sidecar'ы типа `istio-proxy`/`linkerd`/`vault-agent` отфильтровываются).

Сохранение конфига **не применяется на лету**: часть сервисов получает свои секции при сборке
composition root, и частичный подхват дал бы половину приложения на старых настройках. UI после
записи предлагает перезапуск ([ADR-0008](adr/ADR-0008-config-and-profiles.md)).

## 3. Карта команд

### 3.1 Логин / статус

```bash
tsh login --proxy=teleport.example.com:443 --user=user@example.com teleport.example.com
```

- Канал: PTY. Промпты (точные строки, фикстуры):
    - `Enter password for Teleport user user@example.com:`
    - `Enter an OTP code from a device:`
- Успех: exit 0 + блок `> Profile URL: …`. Если сертификат ещё жив — выходит сразу без промптов.

```bash
tsh status --format=json
```

- Канал: exec. Ключевые поля ответа:

```jsonc
{
  "active": {
    "profile_url": "https://teleport.example.com:443",
    "username": "user@example.com",
    "cluster": "teleport.example.com",
    "kubernetes_enabled": true,
    "kubernetes_cluster": "stage-k8s-cluster",   // ← текущий kube-контекст
    "databases": ["dev-postgres", "prod-postgres"],
    "valid_until": "2026-07-29T04:27:47+04:00"   // ← источник обратного отсчёта серта
  },
  "profiles": []
}
```

- Не залогинен → ненулевой exit / пустой `active` — оба случая трактуются как `auth/required`.

### 3.2 DB-прокси

```bash
tsh proxy db --port=6432 --db-user=app --db-name=dev --tunnel dev-postgres --mfa-mode=otp
```

- Канал: PTY (per-session MFA спросит OTP на старте). Долгоживущий процесс.
- **Readiness — не парсить stdout** (форматы строк меняются между версиями Teleport):
  критерий готовности — успешный TCP-connect на `localhost:<port>` (+ опц. `SELECT 1`).
- `--tunnel` ⇒ клиенты подключаются без собственной аутентификации, пока жив прокси.
- Здоровье/деградация: см. §6. Завершение: SIGTERM, при таймауте SIGKILL.
- Порты: стратегия `shared` — включение пресета при живом другом прокси на том же порту
  предлагает переключение (stop → start); EADDRINUSE от чужого процесса — показать `lsof -i :<port>`.

Известные: туннель из пресета может отсутствовать в `tsh db ls`, если на него нет роли — пресет
всё равно валиден, ошибку доступа показываем честно.

### 3.3 Kubernetes

```bash
tsh kube login dev-k8s-cluster          # exec; быстрый, пишет kubeconfig
tsh kube ls --format=json               # exec; список кластеров
tsh kubectl get pods -n apps -o json [--field-selector=status.phase=Running]   # exec
tsh kubectl exec -it <pod> -n apps -c api -- bash                         # PTY
tsh kubectl exec <pod> -n apps -c api -- sh -lc '<cmd>'                   # exec, one-shot
tsh kubectl logs <pod> -n apps -c api --tail=500 [--follow]               # spawn-поток
```

- Текущий кластер — из `tsh status` (`kubernetes_cluster`); перед действием на окружении X
  при несовпадении выполняется `kube login` (прозрачно, со спиннером).
- Реализация M2 (`KubeService`): `kube login` получает `--mfa-mode=otp`, но если сборка tsh
  этого флага не знает (`unknown flag`) — автоматический повтор без него; переключения
  сериализованы очередью (два действия подряд не дерутся за kubeconfig); совпадающий кластер
  вообще не логинится заново.
- Логи и `exec -it` идут PTY-сессиями, one-shot — exec-каналом с PTY-фолбэком при MFA:
  [ADR-0007](adr/ADR-0007-kube-streams-via-pty.md).
- stderr у tsh **раскрашен ANSI** (`\x1b[31mERROR: \x1b[0m…`) — перед показом в UI и перед
  матчингом на «нужен перелогин» его надо снимать (`stripAnsi`), иначе пользователь видит
  `[31mERROR:` (поймано на живом прогоне 2026-08-01).
- Поды из JSON: `metadata.name`, `metadata.creationTimestamp`, `status.phase`,
  `status.startTime`, `status.containerStatuses[].{ready,restartCount}`,
  `spec.containers[].name`. **Age** = `now − creationTimestamp` (рендер в стиле kubectl:
  `3h29m`, `6d1h`).
- `kubectl exec/logs` может потребовать MFA per-session в зависимости от политики кластера —
  exec-канал при интерактивном запросе не выживет, поэтому: `exec -it` всегда PTY;
  для one-shot/logs при ошибке MFA — автоматический повтор через PTY-обёртку.

#### Алгоритм выбора пода (PodSelector)

```
кандидаты = pods
  .filter(name.startsWith(workload.podPrefix))
  .filter(!workload.podExclude.some(маркер в имени))
  .filter(phase == "Running")
  .filter(все containerStatuses.ready)
выбор = argmax(status.startTime)          // «желательно свежайший»
```

UI также позволяет выбрать любой под вручную (US-05) — включая группу «прочее» (поды вне
масок); контейнер для них — первый не-sidecar из `spec.containers[]`.

Реализация — `core/modules/teleport/pods.ts` (`parsePods` / `matchWorkload` / `selectFreshest` /
`resolveContainer` / `defaultContainer`), фикстуры — `__fixtures__/kube.ts` (синтетика, собранная
из кейсов ниже; тесты держатся именно на них).

Кейсы, из-за которых наивная реализация не годится:

- Населённый namespace — это сотни подов, и бо́льшая часть из них в фазе `Succeeded`
  (доработавшие поды прошлых деплоев). Поэтому в таблице по умолчанию включён фильтр
  «только Running», а `Succeeded` — не ошибка и красным не красится.
- Полный `get pods -o json` стоит мегабайты и секунды (почти всё время — установка
  соединения tsh, не объём). Отсюда кэш списка в `KubeService` (15 с) с дедупом параллельных
  запросов: таблица, быстрые действия и трей делят один ответ.
- Рядом с приложением живут sidecar'ы, а прокси-контейнер вполне может стоять в
  `spec.containers[]` **перед** приложением — «первый контейнер из spec» дал бы прокси,
  поэтому `-proxy` в списке sidecar-маркеров.
- Соседние релизы и вспомогательные компоненты (воркеры, крон) бывают **свежее** рабочего
  пода — маска `podPrefix` обязана быть полной, иначе «свежайший» уедет в чужой релиз.
  Ровно для этого в конфиге есть `podExclude`.

### 3.4 SQL и дампы

- В самом tsh headless-SQL нет; `tsh db connect` — это обёртка над psql (интерактив).
- **Встроенная консоль** ([ADR-0009](adr/ADR-0009-sql-console.md)): драйвер `pg` →
  `127.0.0.1:<port>` активного туннеля, `user`/`database` из пресета, без пароля (туннель
  аутентифицирован, TLS не нужен); `statement_timeout` из конфига; результат → таблица.
  Соединение живёт один запрос: при стратегии `shared` тот же адрес после переключения
  тумблера ведёт уже в другую базу.
- Боевой пресет (`dangerous`): мутирующий запрос — только с подтверждением, всё остальное
  выполняется в `BEGIN READ ONLY` (эвристика решает, спрашивать ли; отбивает — сервер).
- `SELECT 1` тем же драйвером = живой health-check туннеля: ProxySupervisor доводит прокси до
  `healthy` только через него, дальше повторяет раз в минуту.
- **psql в терминале**: PTY `psql -U <user> -h 127.0.0.1 -p <port> <dbName>`.
- **pg_dump-пресет**: PTY-сессия `sh -lc '<шаблон из конфига>'` (подстановки `{port}`,
  `{dbName}`, `{dbUser}`, `{env}`, `{file}`, `{date}`) — редирект в файл делает шелл;
  индикация — рост размера файла, по завершении — системное уведомление.

## 4. Аутентификация и MFA

### 4.1 Автоответ на промпты

Цепочка PromptPipeline (архитектура — [03, §4.3](03-architecture.md#43-promptpipeline-цепочка-обработчиков)):

| Промпт (фикстура)                          | Обработчик      | Источник                                            |
|--------------------------------------------|-----------------|-----------------------------------------------------|
| `Enter password for Teleport user <user>:` | PasswordHandler | Keychain (`CredentialStore.getPassword`)            |
| `Enter an OTP code from a device:`         | TotpHandler     | `otplib.authenticator.generate(secret)` из Keychain |
| прочее / отказ пользователя / нет кредов   | AskUserHandler  | inline-поле в UI, ввод → в тот же PTY               |

- Таймаут распознавания: если сессия ждёт ввода (нет новых данных, процесс жив), а матчер
  ничего не узнал за N сек — показать терминал пользователю (фолбэк «просто покажи PTY»).
- Отвергнутый OTP (`Invalid …`/повторный промпт): одна повторная попытка на границе
  следующего 30-сек окна TOTP, затем ручной ввод.
- Кластер предпочитает webauthn ⇒ **все** автоматизируемые команды получают `--mfa-mode=otp`,
  иначе tsh уйдёт в Touch ID/ключ и PTY-автоответ не сработает.

### 4.2 Собственный TOTP-девайс приложения

Обычный 2FA-аппликейшн — sandboxed-приложение без API/URL-scheme/CLI, интеграция с ним
невозможна. Вместо этого приложение регистрирует **свой** девайс (Teleport допускает
несколько):

1. Мастер настроек запускает PTY: `tsh mfa add --type TOTP --name xet-infra-gui`.
2. tsh просит подтверждение существующим девайсом (код из старого приложения — единственный
   ручной ввод).
3. tsh выводит QR + **секрет в открытом виде** — мастер парсит секрет, кладёт в Keychain,
   просит подтверждающий код (генерируем сами же) и завершает регистрацию.
4. Дальше все OTP-промпты закрываются автоматически. Девайс можно отозвать
   (`tsh mfa rm xet-infra-gui`) — кнопка в настройках.

Реализация M1 — `MfaEnrollService` (кнопка «Создать TOTP-девайс» в настройках): сессия мастера
видна обычным PTY-табом, watcher ловит секрет (`otpauth://…secret=` либо `Secret key:`) и
промпт нового девайса (`MFA_ADD_PATTERNS` в prompts.ts). ⚠️ Промпты мастера реконструированы
по исходникам tsh 17.x и вживую пока НЕ сверены — при первом прогоне сверить дословно и
обновить фикстуры `MFA_ADD_*` (NFR-7). Промпт СУЩЕСТВУЮЩЕГО девайса отличается от логинного
(`…from a *registered* device`), поэтому обычный PromptPipeline его не перехватит — и не должен.

### 4.3 Хранение кредов

- Интерфейс `CredentialStore` (пароль, TOTP-секрет). Сейчас: Electron `safeStorage`
  (ключ в macOS Keychain). Будущее: адаптер удалённого API (отдельный бэкенд-проект) — FR-A2.

## 5. Health-мониторинг

`HealthMonitor`, тикер 15–30 с + внеочередной прогон по `powerMonitor.on('resume')` и после
перелогина:

| Проверка                | Метод                                                                                                             | Реакция                                           |
|-------------------------|-------------------------------------------------------------------------------------------------------------------|---------------------------------------------------|
| Сертификат              | локальный отсчёт от `valid_until` (без вызова tsh каждый тик; refresh `tsh status` раз в ~5 мин и после операций) | < 30 мин — жёлтая иконка; истёк — `auth/required` |
| Прокси-процесс          | exit-событие PTY                                                                                                  | Supervisor: рестарт с backoff                     |
| Прокси-порт             | TCP-connect `localhost:<port>`, таймаут 1–2 с                                                                     | fail ⇒ `degraded`                                 |
| Туннель насквозь (опц.) | `SELECT 1` через `pg`                                                                                             | fail при живом порте ⇒ `degraded` + подсказка     |

## 6. Определение «нужен перелогин»

Триггеры события `auth/required` (любой из):

1. `valid_until` в прошлом / отсутствует.
2. exec-команда упала: ненулевой exit + stderr матчится на паттерны истёкшей сессии
   (`expired`, `re-?login`, `access denied` — набор в фикстурах, дополняем по мере встречи).
3. Health-probe прокси деградировал и **одновременно** сертификат близок к нулю (симптом
   «прокси висит, запросы не идут» из практики).
4. PTY-сессия неожиданно попросила пароль (PromptPipeline сообщает — сам и закроет).

Реакция — поток [02, §6.2](02-ux.md#62-протухший-сертификат): баннер → `tsh login` (авто) →
`ProxySupervisor.restartMarked()` (все db-прокси имеют `restartOnRelogin: true`).

## 7. Edge cases / известные грабли

| Ситуация                                                             | Поведение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
|----------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| tsh не найден (запуск из Dock, PATH пуст)                            | PATH-резолв через login-shell ([03, §8](03-architecture.md#8-path-и-окружение-процессов-классические-грабли-macos)); иначе — wizard просит путь                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Авто-ответы терминала портят пароль** (проверено на живом логине)  | tsh при старте шлёт OSC 11 (запрос фона) и DSR (позиция курсора); xterm авто-отвечает через `onData`, и из-за задержки Electron ответ попадает в stdin поверх пароля → `invalid credentials`. Фикс: `stripTerminalReports` вырезает CPR/DA/DSR/OSC из ввода в PTY на auth-сессиях (флаг `sanitizeTerminalReports`); ответы пайплайна идут мимо фильтра. Для интерактивных exec-сессий фильтр выключен — там эти ответы нужны программам. Побочно этим же снят и косметический `^[]11;rgb:…`/`^[[1;1R`: раз ответ не доходит до PTY, tty его не эхоит |
| **Дубль вывода при восстановлении xterm**                            | renderer подписывается на `session/data` раньше снапшота ring buffer (иначе дыра) — «хвост» снапшота и уже пойманные живые чанки пересекаются. Фикс: абсолютный watermark потока — `SessionManager` нумерует произведённые символы (`cursor` в снапшоте, `end` в каждом data-событии), `replaySlice` (shared/stream) режет из живых чанков только то, что правее watermark. Без дыр и без дублей независимо от гонки                                                                                                                                 |
| **Общий порт ⇒ соединение из прошлой базы** (M3)                     | при стратегии `shared` адрес туннеля один на все пресеты: переиспользованное соединение после переключения тумблера отвечало бы из предыдущей базы правдоподобным результатом. Поэтому SQL-консоль открывает соединение на каждый запрос ([ADR-0009](adr/ADR-0009-sql-console.md))                                                                                                                                                                                                                                                                     |
| **`localhost` вместо `127.0.0.1`** (M3)                              | `tsh proxy db` слушает IPv4-loopback; `localhost` на macOS может разрешиться в `::1` и дать `ECONNREFUSED` на ровном месте. И драйвер, и команда `psql` идут в `127.0.0.1` явно                                                                                                                                                                                                                                                                                                                                                                       |
| **Открытый порт ≠ живая база** (M3)                                  | TCP-probe видит только локальный слушающий сокет: туннель может стоять, а сессия к БД по ту сторону Teleport развалиться. `healthy` выставляется лишь после `SELECT 1` драйвером; ошибка попадает в подпись прокси («порт открыт, но база не отвечает»)                                                                                                                                                                                                                                                                                                |
| **Мутирующий запрос, похожий на чтение** (M3)                        | `select nextval('s')`, `with … delete … returning`, `explain analyze update` — текстовая эвристика тут ошибётся. На `dangerous`-пресете неподтверждённый запрос идёт в `BEGIN READ ONLY`, и PostgreSQL отбивает его сам (`25006`); проверено вживую                                                                                                                                                                                                                                                                                                   |
| Запрос повис на уровне сети (туннель жив, ответа нет)                | серверный `statement_timeout` о таком не узнает — поверх него клиентский `query_timeout` (statement_timeout + 5 с), иначе спиннер в UI навсегда                                                                                                                                                                                                                                                                                                                                                                                                       |
| Порт 6432 занят другим прокси приложения                             | предложение переключить окружение (стратегия `shared`)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Порт занят чужим процессом                                           | ошибка + вывод `lsof -i :6432` + выбор другого порта                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **`kubectl logs`/`exec` под PTY молчат** (поймано на живом кластере) | tsh спрашивает терминал (`ESC]11;?`, `ESC[6n`) и **ждёт ответа**, а `sanitizeTerminalReports` — фильтр, который спасает stdin auth-сессий, — эти ответы срезал: таб «работает», в ring buffer два запроса и ни строчки логов. Для kube-команд (`logs`, `exec -it`, one-shot в PTY) фильтр выключен; тест `TshClient.test.ts` держит флаг                                                                                                                                                                                                             |
| Под умер во время exec-сессии (rollout)                              | сессия `exited`; таб предлагает «переподключиться к свежему поду» (кнопка перезапускает то же действие без имени пода — PodSelector выберет заново)                                                                                                                                                                                                                                                                                                                                                                                                  |
| Кэш списка подов отдаёт мёртвый под                                  | кэш сбрасывается по сигналу: kube-сессия ушла в `exited`/`failed` (значит был rollout) → «переподключиться к свежему» выбирает по свежему списку; плюс TTL 15 с и кнопка «Обновить» (`force`)                                                                                                                                                                                                                                                                                                                                                        |
| Быстрое действие сразу после старта приложения                       | `tsh status` мог ещё не приехать: пустой кэш статуса не значит «контекста нет» — `KubeService` дожидается статуса, иначе делал лишний `kube login` в уже активный кластер                                                                                                                                                                                                                                                                                                                                                                            |
| Имя пода из таблицы устарело (под уехал между обновлениями)          | действие возвращает ошибку «список устарел, обнови», а не `exec` в несуществующий под                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| `kube login` на другой кластер во время активной exec-сессии         | не блокируем: exec уже установлен; предупреждение в UI                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| Сон ноутбука                                                         | по resume — немедленный health-check всех сессий                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Смена версии Teleport                                                | фикстуры промптов/JSON в тестах (NFR-7); min_client сейчас 16.0.0                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `tools_auto_update`                                                  | на кластере выключен; если включат — tsh может «сам обновиться», путь остаётся валидным                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
